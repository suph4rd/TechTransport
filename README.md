# Tech Transport

Локальный MVP поиска техники в Беларуси. Реализованы этапы 1–2 из `start_project_plan.md`: основа приложения, вход по локальному SMS-коду, профиль и сессии. Стек: FastAPI, Vue 3 + TypeScript, PostgreSQL, Alembic и Docker Compose.

## Запуск

Нужны Docker Engine / Docker Desktop и Docker Compose v2. Из корня проекта:

```sh
cp .env.example .env
docker compose up --build -d
```

Первый запуск скачивает образы и зависимости. Backend ожидает готовность PostgreSQL и автоматически применяет миграции перед запуском. Frontend ожидает готовность backend.

- Приложение: http://localhost:5173
- OpenAPI: http://localhost:8000/docs
- Проверка процесса: http://localhost:8000/api/health/live
- Проверка подключения к БД: http://localhost:8000/api/health/ready

Frontend обращается к `/api` через Vite proxy: браузеру не требуется доступ к внутреннему имени `backend`. Порты доступны только локально. Настройки портов, БД и логирования находятся в `.env.example`; файл `.env` не включается в Git. Если пароль содержит специальные символы URL, его значение в `DATABASE_URL` необходимо кодировать; для локального Compose используйте пароль из букв, цифр, дефисов и подчёркиваний.

## Управление

```sh
docker compose ps
docker compose logs -f backend frontend db
docker compose restart
docker compose down
docker compose up -d
```

`restart` перезапускает существующие контейнеры. `down` удаляет контейнеры и сеть, сохраняя данные. После изменения зависимостей, кода или переменных окружения выполните `docker compose up --build -d`.

**`docker compose down -v` удаляет БД и фотографии без восстановления.** Не используйте эту команду для обычного перезапуска. Данные PostgreSQL и фотографии хранятся в отдельных именованных volumes `postgres_data` и `photos_data`. Изменение пароля в `.env` не меняет пароль уже инициализированной БД.

## Миграции

```sh
docker compose exec backend alembic current
docker compose exec backend alembic upgrade head
docker compose exec backend alembic downgrade -1
```

Для создания миграции с сохранением файла в рабочем каталоге:

```sh
docker compose run --rm -v "$(pwd)/backend:/app" backend alembic revision --autogenerate -m "describe change"
```

Новые модели нужно импортировать в `migrations/env.py`, чтобы Alembic видел их metadata. Начальная миграция `0001` фиксирует основу; `0002` добавляет пользователей, коды входа и сессии. Сессия БД закрывается после запроса, при исключении откатывается; изменяющие операции должны явно вызывать `commit()`.

## Проверки

```sh
docker compose exec backend python -m pytest -q
docker compose exec frontend npm run build
```

Прямые зависимости закреплены в `backend/requirements*.txt` и `frontend/package.json`, транзитивные Python-зависимости закреплены в `backend/requirements.lock`, npm использует `package-lock.json`. Python 3.12 и Node 22 поставляются в контейнерах.

Ошибки API имеют формат `{"error":{"code":"...","message":"...","details":[]}}`. Ответ readiness возвращает 503 при недоступности БД. Тела запросов, query string, cookies, SQL-параметры и тексты внутренних исключений не журналируются. Access log Uvicorn выключен. Единственное исключение для кодов — локальная SMS-заглушка: её журнал содержит телефон и код входа.

Это окружение локальной разработки: frontend работает через Vite dev server. Справочник, карточки, фотографии и карта запланированы в этапах 3–7. Настоящие SMS и production-развёртывание пока не реализованы.

Известное ограничение проверок: Starlette сообщает о будущей замене httpx на httpx2 в тестовом клиенте; текущие тесты проходят. Вход и профиль проверены в Chrome при ширине 390 и 1440 px; проверен полный цикл входа, редактирования имени, обновления сессии и выхода через PostgreSQL, включая сохранение сессии после перезапуска backend.


## Вход и профиль

Откройте приложение, введите мобильный номер Беларуси и нажмите «Получить код». Поддерживаются форматы `+375 29 123-45-67`, `80291234567` и `291234567`; в БД сохраняется `+375291234567`. Номер нельзя изменить через профиль, и он остаётся уникальным у отключённых пользователей.

В другом терминале откройте локальный журнал:

```sh
docker compose logs -f backend
```

Найдите строку `LOCAL SMS phone=… code=…` и введите шестизначный код. Код действует 5 минут, повторный запрос возможен через минуту, после 5 неверных попыток нужен новый код. Повторная отправка заменяет предыдущий код. Успешно использованный код недействителен. Пользователь создаётся после первой успешной проверки. SMS реально не отправляются; журнал с кодами предназначен только для локальной разработки.

В профиле можно сохранить отображаемое имя, обновить сессию и выйти. Сессия действует 7 дней, обновление заменяет её идентификатор и CSRF-токен. Сессии и ограничения кодов сохраняются в PostgreSQL. Отключённый пользователь не может войти, обновить сессию или использовать её для доступа к профилю.

Для назначения администратора сначала войдите с нужным номером, затем выполните:

```sh
docker compose exec backend python -m app.admin +375291234567
```

Команда не создаёт пользователей и не включает отключённые аккаунты. Проверка роли `require_admin` подготовлена для административных методов следующих этапов; роль видна в профиле после обновления страницы.

Методы API:

- `POST /api/auth/code` — запрос кода, JSON `{ "phone": "+375291234567" }`.
- `POST /api/auth/verify` — вход, JSON с `phone` и `code`.
- `GET /api/auth/me` — профиль и CSRF-токен.
- `PATCH /api/auth/me` — изменение имени, JSON `{ "display_name": "Андрей" }`.
- `POST /api/auth/refresh` — замена сессии и продление на 7 дней.
- `POST /api/auth/logout` — удаление текущей сессии.

Запрос и проверка кода требуют заголовок `X-CSRF-Token: login`. Остальные изменяющие запросы требуют `X-CSRF-Token` со значением `csrf_token` из ответа входа, профиля или обновления сессии. Cookie `tt_session` имеет `HttpOnly`, `SameSite=Lax` и путь `/api`; идентификаторы сессий хранятся в БД в виде SHA-256, коды — как scrypt-хеши с индивидуальной солью. Frontend не сохраняет токены в localStorage.

`ALLOWED_ORIGINS` задаёт разрешённые источники изменяющих запросов через запятую; при смене порта frontend обновите эту настройку. Межсайтовые запросы блокируются, CORS не включён. `COOKIE_SECURE=false` используется для локального HTTP; при переходе на HTTPS задайте `true`.

Имя проекта Compose определяет имена контейнеров и volumes. Если окружение ранее запускалось с `-p`, используйте то же имя или задайте `COMPOSE_PROJECT_NAME` в локальном `.env`, чтобы команды работали с существующими данными. В текущем рабочем окружении сохранено имя `techtransportbackend`.
